# NaviFold Next 0.9.0-dev

기존 버전은 v0.8.4 태그로 보존하고 다음 기능은 `develop/0.9.0`에 분리했습니다.
앱 ID는 `dev.navifold.player.next`, QA는 `.next.qa`입니다.

## 구현

- 추천곡 제목의 작은 ✦ 표시와 길게 누르기 메뉴.
- NOW PLAYING의 AI 상태에서 현재 곡 메뉴 및 최근 기록 접근.
- 후보 생성에서 사용한 메타데이터의 일치 조건을 표시. ChatGPT의 내부 판단을 추측하거나 설명 생성을 추가 호출하지 않습니다.
- 더 듣기 / 덜 듣기 / 선호 초기화는 곡별 명시적 선호를 저장하고 진행 중인 오래된 추천 요청을 무효화합니다. 선호 초기화는 감상 기록 전체 삭제가 아닙니다.
- 이번 큐에서 제외는 선택한 항목 하나만 제거합니다. 같은 ID의 다른 항목과 선호는 유지하고 현재 항목 삭제에 따른 관찰 종료도 학습하지 않습니다.
- 로그인 성공 후 한 번만 큐 복원. 메타데이터·중복 항목·현재 인덱스·위치·반복과 셔플 켜짐 상태를 저장합니다. 셔플의 무작위 순열은 재생성합니다.
- 자동으로 재생하지 않으며 현재 서버·음질 설정으로 URL을 새로 만듭니다. 저장 데이터에 스트림 URL·인증정보·파일 경로·코멘트를 넣지 않습니다.
- 복원 중 사용자가 큐를 변경하거나 계정이 바뀌면 오래된 작업을 취소합니다. 로그아웃은 큐 캐시와 대기 중 쓰기를 무효화합니다.
- 큐 변경은 서비스의 다음 갱신 시 저장하고 재생 위치는 약 10초 간격으로 저장합니다. 강제 종료 시 마지막 수 초가 반영되지 않을 수 있습니다. 복원 한도는 5,000곡이며 초과 시 이전 큐를 잘못 복원하지 않도록 저장본을 제거합니다.

## 검증

- JDK 21, SDK 35: `testDebugUnitTest lintDebug assembleDebug assembleQa` 성공.
- 단위 테스트 84개 통과. 잘못된 스키마·위치·누락 ID·큰 큐, 중복 항목, 민감 필드 제외, 추천 설명의 근거, 삭제 관찰의 1회 무시 포함.
- Lint 오류 0개 / 경고 45개. 큐 저장의 `commit()`은 순차 작업 스레드에서 처리하며 로그아웃 삭제는 저장 세대 잠금 아래에서 수행합니다.
- Pixel 10 Pro Fold 에뮬레이터에서 실제 Media3 서비스 사용.
- 앱 강제 종료 후 3곡의 ID·중복 순서·현재 인덱스 1·34,567ms 위치 복원, playWhenReady=false 확인.
- 실제 UI 메뉴로 비선호(-1)·초기화(0)·선호(+1) 저장 및 비선호 판정 확인.
- 현재 곡 한 번 제외 후 나머지 중복 ID 2곡 및 기존 선호 유지.
- 빈 큐로 재시작해도 복원되지 않음, 다른 계정으로 이전 큐가 넘어가지 않음, 로그아웃 후 저장본 없음.

학습을 켠 상태에서도 이번 큐에서 제외 전후 이벤트 수가 6 → 6으로 유지됐습니다. 큐 행 길게 누르기 메뉴도 확인했습니다.
