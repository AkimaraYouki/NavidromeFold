# NaviFold Next 0.9.1-dev 검증

2026-10-20 · versionCode 25 · 기존 Next 앱 ID 유지.

## 변경

- 자연어 요청 → 검색 조건 해석 → 보유 곡 최대 40개 후보 → 모델의 후보 ID 선택 → 결과 미리보기·재생·큐 추가.
- 예시 버튼과 저장 데이터만 사용하는 검색. 로컬 결과를 ChatGPT 실시간 결과와 구분합니다.
- 앨범·수록곡 사전 분석: 3앨범/60곡 단위, 앨범 메타데이터 반복 전송 감소, 시작·중단·이어서 처리.
- `smart-library.db` 버전 3의 `track_profiles`에 원본 태그와 분리해 저장합니다. 지문 변경·만료에 따른 재분석, 불확실한 추정의 낮은 활용도, 앨범 카드의 GPT 추정 표시.
- 태그 누락이 기존 보완 값을 지우는 문제와 보완 전에 후보를 제외하는 순서 수정.
- 첫 100곡만 가져오던 대체 경로 개선. 전체 곡 페이지 조회·캐시와 제한된 구형 서버 대체 경로.
- 작은 라이브러리의 최근 제외 완화, 현재/예정 곡 중복 방지는 유지하면서 지난 재생 항목 재추천 허용.
- 엄격 모드·명시된 장르/음악권/언어 충돌·비선호 조건은 유지합니다. 원인별 상태와 재시도 대기를 구분합니다.

## 빌드

JDK 21 / SDK 35에서 `testDebugUnitTest lintDebug assembleDebug assembleQa` 성공.
단위 테스트 **117개 통과**, Lint **오류 0개 / 경고 45개**.
일반 APK에 QA receiver가 포함되지 않음을 manifest로 확인했습니다.

## 에뮬레이터와 실제 Media3 서비스

합성 235앨범·705곡, 무음 스트림을 사용하는 Pixel 10 Pro Fold 에뮬레이터에서 수행했습니다.

- 전체 705곡 색인, 첫 100곡 밖 후보 검색.
- 장르 없는 후보 회복, Pop/J-pop 및 알려진 언어 충돌 차단.
- 최근 이력만 완화하고 비선호는 유지. 엄격 모드는 임의 확장하지 않음.
- 테스트 모델이 태그 없는 후보를 선택하는 경로, 프롬프트의 서버 ID/URL/암호 제외, 잘못된 ID의 로컬 대체, 취소한 요청의 결과 폐기.
- 앨범 단위 분석 묶음, 프로필 저장 후 중복 분석 방지, 태그 없는 곡의 캐시 분위기 검색, 메타데이터 변경 시 무효화, DB 버전 3.
- 서비스의 실제 자동 보충: 태그 없는 큐 1곡 → 3곡, `태그 일부 없음` 상태.
- 지난 곡 재추천: 현재 인덱스 2인 3곡 큐 → 5곡. 현재 곡은 중복 추가하지 않고 지난 2곡만 다시 붙임.
- Pop/Synth-pop 보충, 추천곡으로 이동해도 기준 유지, J-pop 직접 선택 시 기준 전환, 엄격 모드 후보 부족, 다양하게 모드 회귀 검증.
- 실제 UI로 자연어 입력·로컬 결과·빈 큐에 일시정지로 추가·검색 취소 시 큐 보존 확인.
- 설정의 사전 분석 시작/이어가기 버튼과 내부 DB 저장 현황 화면 확인.

## 확인하지 않은 범위

실제 ChatGPT 계정의 추론 호출·전체 라이브러리 분석 품질·플랜 사용량은 확인하지 않았습니다. 모델 경로는 테스트 구현을 주입해 결과 검증·캐시 처리를 확인했고, 외부 전송 형식은 기존 계정 연결을 재사용합니다. 사용자의 실제 음악 데이터가 미리 분석 완료된 상태를 뜻하지 않습니다.

휴대폰이 연결되어 있지 않아 이번 버전은 에뮬레이터로 검증했습니다. 대규모 라이브러리의 장시간 분석·배터리 및 앱 강제 종료/계정 변경과 전체 분석 작업의 모든 조합도 미검증입니다. 분위기·활기는 메타데이터와 모델 지식을 바탕으로 한 추정이며 음원 분석 결과나 객관적 확신도 측정이 아닙니다.
