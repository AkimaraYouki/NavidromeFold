# NaviFold 0.7.8 · Album queue controls

2026-10-17

## 사용
- 앨범 커버를 길게 누르면 해당 앨범 전곡을 디스크·트랙 순서로 큐 끝에 추가합니다. 현재 화면과 재생 위치를 유지합니다. 큐가 비어 있어도 자동 재생하지 않고 대기 상태로 준비합니다.
- 앨범 상세에서 곡을 길게 누르면 선택 모드가 됩니다. 다른 곡은 탭으로 추가/해제합니다. Play next는 현재 곡 바로 뒤, Play later는 큐 맨 뒤에 넣습니다. 선택한 순서와 관계없이 앨범에 표시된 트랙 순서를 유지합니다.
- Remove는 선택한 곡 ID에 해당하는 큐 항목을 모두 제거합니다. 큐에 같은 곡이 여러 번 있으면 모두 제거하며 음악 파일은 삭제하지 않습니다. 선택 해제 버튼이나 뒤로 가기로 선택 모드를 종료합니다.
- 큐 팝업의 AI 스위치로 자동 큐 보충을 켜고 끕니다. 큐에 1곡 이상 있을 때 활성화됩니다. 마지막 곡을 빼거나 큐를 비우면 자동으로 OFF·비활성화하며 늦게 도착한 추천도 적용하지 않습니다. 설정의 자동 보충도 빈 큐에서는 켤 수 없습니다.
- 앨범 상세 ALBUM NOTES에 장르·레이블과 MusicBrainz 보완 출처를 작게 표시합니다. 펼친 화면에서는 커버/버튼 아래 여백을 사용하며 정보 패널은 스크롤할 수 있습니다.
- AI 버튼을 누르면 현재 선택한 ChatGPT 모델로 짧은 한국어 앨범 요약을 생성합니다. 로그인과 모델 선택이 필요합니다. 제공한 메타데이터만 요약하도록 지시하며 음원 분석·평론을 지어내지 않도록 제한합니다.
- 요약은 서버/계정·앨범·메타데이터 기준으로 30일 캐시합니다. 앨범을 열 때마다 AI를 호출하지 않습니다. OpenAI에 앨범명·가수·장르·레이블·연도·곡 개수·최대 30개 트랙 제목만 보내며 음원/경로/인증정보는 보내지 않습니다. GPT-6 제외를 유지합니다.

## 구현
- QueueEdits로 다음/나중 삽입과 뒤에서부터의 중복 곡 제거를 통합했습니다. 큐 추가 작업은 순차 처리하며 일시정지 중에는 그대로 유지합니다.
- 큐 팝업이 서비스의 자동 보충 설정을 공유합니다. 외부 설정 변경을 반영하며 닫기/제스처 취소 시 리스너를 해제합니다.
- 큐 팝업의 유리 효과 아래에 불투명한 중성 바탕을 넣어 밝은 시스템 다이얼로그 배경이 비쳐 대비가 낮아지는 문제를 수정했습니다.
- 앨범 정보의 외부 조회는 별도 작업 스레드에서 처리하여 앨범/서버 목록 요청을 막지 않습니다. 외부 정보로 원본 트랙의 아티스트·재생 시간을 덮어쓰지 않습니다.
- SQLite v1 → v2는 album_notes 테이블만 추가합니다. 기존 음악 색인·취향·이벤트·MusicBrainz 캐시는 유지합니다. 감상 데이터 삭제 시 앨범 요약 캐시도 함께 삭제합니다.
- 화면을 전환하거나 계정·모델이 바뀌면 오래된 요약 결과를 다른 앨범 화면에 적용하지 않습니다.

- assembleDebug / assembleQa / testDebugUnitTest / lintDebug 성공. 단위 테스트 50개, lint 오류 0개 / 경고 40개.
- 실제 에뮬레이터 UI에서 앨범 길게 누르기 → 3곡 추가·정지 상태 유지 확인. 두 앨범을 연달아 추가해 6곡 순서 확인.
- 큐 팝업 AI ON 저장, 비운 뒤 OFF·disabled 확인.

- 접힘/펼침 선택 UI, 뒤로 가기의 선택 해제, 장르·레이블 정보 카드 표시를 확인했습니다.
- 기존 v1 합성 DB의 트랙 1건이 v2 업그레이드 뒤에도 보존됨을 확인했습니다.
- 합성 요약 캐시를 넣어 화면 재표시, 다른 계정에서 읽히지 않음, 메타데이터가 달라지면 캐시가 사용되지 않음을 확인했습니다. 합성 캐시 문구는 QA에만 넣었으며 프로덕션 APK에는 포함하지 않습니다.
- 실제 ChatGPT 계정 로그인과 생성 응답은 이번에 실행하지 않았습니다. 로그인 전 안내와 요약 프롬프트의 전송 범위·길이 제한을 검증했습니다. 실제 MusicBrainz 응답 품질은 이전 버전의 제한과 같습니다.
