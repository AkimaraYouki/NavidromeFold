# 음악 검색·추천과 분석 캐시

NaviFold Next 0.9.1-dev 기준입니다. 보유한 Navidrome 곡에서만 고릅니다.

## 자연어 검색

상단 ✦ → 원하는 상황·분위기 입력 → 추천 → 결과에서 재생 또는 큐 추가.

- “기분이 우울해, 신나는 노래”는 현재 감정과 원하는 음악을 구분합니다.
- “공부하고 싶어, 차분한 노래”는 차분한 음악을 우선합니다.
- ChatGPT가 요청을 작은 검색 조건으로 해석하고, 로컬 색인에서 최대 40곡을 찾은 뒤 후보 ID만 선택합니다. 일반적으로 수동 검색 한 번에 해석·선택 최대 두 번의 모델 요청을 사용합니다.
- 기존 큐의 장르가 새 자연어 요청을 강제로 제한하지 않습니다.
- 음원·서버 URL·서버 ID·암호를 모델에 보내지 않습니다. 요청 문장과 음악 메타데이터 및 최근 감상 요약을 사용합니다.
- 로그인·모델 선택·계정 한도에 따라 이용 가능 여부가 달라집니다. GPT-6 제외는 유지합니다.
- 취소하거나 계정을 바꾸면 뒤늦은 결과로 큐를 바꾸지 않습니다.

**저장 데이터로만 추천**은 추가 GPT 요청 없이 간단한 분위기 키워드·태그·저장된 GPT 분석으로 찾습니다. 자유로운 문장 이해는 실시간 ChatGPT 검색보다 제한됩니다. 연결 실패 시 로컬 대체 설정도 따릅니다. 화면에서 LOCAL과 ChatGPT 결과를 구분합니다.

## 미리 분석해 저장하기

설정 → SMART DJ → **앨범·곡 분위기 데이터** → **분석 시작 · 이어서**.

- 앨범 메타데이터와 수록곡 정보를 한 번에 최대 3앨범·60곡씩 보냅니다. 반복되는 앨범 정보는 묶어 토큰 사용을 줄입니다.
- 곡별 분위기, 추정 활기, 보컬/연주 여부와 모델의 확신도를 저장합니다.
- 실제 음원을 듣거나 BPM·음색을 측정하는 기능은 아닙니다. 모델에 정보가 부족하면 모름으로 반환하도록 요청합니다. 모델 확신도는 측정된 정확도가 아닙니다.
- 추정 정보는 원본 장르·연도·앨범 태그를 덮어쓰지 않습니다.
- 앱 내부 `smart-library.db`의 `track_profiles`에 서버·계정별로 보관합니다. 기존 곡·앨범 정보는 `tracks` 색인에 있습니다.
- 제목·가수·앨범·연도·장르·BPM 등 확인된 메타데이터 지문이 바뀌면 분석 결과를 재사용하지 않습니다. 일반 결과는 90일, 확신도 낮은 결과는 2일 캐시합니다.
- 새 곡·변경 곡·만료된 곡만 이어서 분석합니다. 사용자가 시작하며 검색할 때마다 전체 분석을 돌리지 않습니다.
- 중지하면 완료한 묶음은 유지합니다. 모델/한도 오류 시 중단하며 자동으로 유료 API 키 결제로 전환하지 않습니다.
- 확신도 60 이상인 분위기만 로컬 분위기 점수와 자동 추천 유사도에 활용합니다. 앨범 정보 카드에는 수록곡의 저장 결과를 `GPT 추정`으로 표시합니다.

## 자동 큐가 막히던 조건 처리

자동 보충은 AI 스위치가 켜져 있고 재생 중이며 반복·셔플이 꺼져 있을 때, 남은 곡 3개 이하에서 시작합니다.

1. 기존 색인에서 장르 조건에 맞는 후보를 찾습니다.
2. 없으면 서버의 전체 곡 목록을 페이지로 조회합니다. 첫 100곡만 확인하고 끝내지 않습니다. 정상 조회 결과는 6시간 재사용합니다.
3. 빈 검색을 지원하지 않는 서버에는 제한된 무작위 목록 대체 경로를 둡니다.
4. 곡·앨범 상세와 선택적 MusicBrainz로 누락 정보를 보완한 뒤 후보를 다시 검사합니다. 빈 응답 값으로 기존 보완 태그를 지우지 않습니다.
5. 자연스럽게 모드에서 여전히 부족하면 장르가 알려지지 않은 곡도 후보에 넣습니다. 알려진 Pop → Jazz/J-pop 등의 충돌을 임의로 풀지는 않습니다. 태그가 없는 경우의 불확실성은 상태에 표시합니다.
6. 최근 재생 제외 때문에 작은 라이브러리가 소진되면 최근 제한만 완화합니다. 현재 곡·예정 곡과 비선호 곡은 계속 제외합니다. 이미 들은 큐의 지난 항목은 다시 추천할 수 있습니다.
7. 실제로 후보가 없으면 큐 밖 곡 없음, 엄격 모드 불일치, 장르·음악권·언어 조건 불일치 등을 구분합니다. 수 분 동안 일반적인 태그 오류만 표시하던 대기를 줄였습니다.

| 모드 | 조건 |
| --- | --- |
| 엄격하게 | 같은 장르. 태그가 없으면 임의 확장하지 않음 |
| 자연스럽게 | 가까운 장르 우선, 정보 보완 후 누락 태그 후보 허용 |
| 다양하게 | 장르·음악권·언어 제한 해제 |

명시된 언어·음악권 충돌은 엄격하게/자연스럽게에서 유지합니다. 알려지지 않은 언어·음악권을 가수 이름으로 추정하지 않습니다. 조건에 맞는 곡이 실제로 없거나 모두 비선호/예정 큐에 있으면 보충하지 않을 수 있습니다.

ChatGPT 자동 보충 요청은 최소 2분 간격·시간당 최대 6회입니다. 사용자가 시작하는 자연어 검색·분석 작업과 별도입니다. 외부 실패 시 설정에 따라 로컬 추천을 사용합니다.

## 검증 범위

단위 테스트, 합성 라이브러리, 에뮬레이터 재생 서비스와 실제 UI로 검증했습니다. 실제 사용자 ChatGPT 계정으로 분석 데이터 전체를 생성하거나 사용자의 실제 음원 라이브러리에서 결과 품질을 검증하지는 않았습니다.

계정 추론은 [OpenAI 공식 모델·추론 문서](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)의 흐름을 따르며 기존 OAuth·`store=false`·`stream=true`·완료 이벤트 확인을 재사용합니다.

### ChatGPT 로그인

Next는 기존 앱과 계정 저장 공간이 별도입니다. 최초 등록에서는 NaviFold라는 이름을 사용자가 수정할 수 있습니다. 승인 뒤 통신이 실패해도 발급된 등록 ID는 보관해 재로그인에 재사용하며, 계정·토큰은 서명과 신원을 검증한 뒤 저장합니다.
브라우저 승인 후 **NaviFold로 돌아가기**를 누르면 앱이 열린 뒤 로그인 코드를 교환합니다. 브라우저가 앞에 있는 동안 백그라운드 통신 제한에 걸리지 않도록 대기하며, 승인 코드는 디스크에 저장하지 않습니다.
설정 → ChatGPT 추천의 **최근 로그인 상태**에서 승인 대기·코드 교환·계정 서명 확인 등 마지막 단계를 확인할 수 있습니다. **연결 검사**는 로그인 없이 서버 도달 여부만 확인합니다.
공식 흐름: [Registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).
